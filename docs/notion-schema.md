# Notion DB 구조

데이터베이스 이름: `산업·직무 인사이트 DB`

| 속성 | 형식 | 값 또는 설명 |
|---|---|---|
| 자료명 | 제목 | 원문 제목 |
| 자료 목적 | 선택 | 직무 공부, 산업·기업 동향 |
| 원문 링크 | URL | 정리된 원문 주소이자 중복 판정 기준 |
| 발행일 | 날짜 | 원문에서 확인한 날짜 |
| 출처 | 텍스트 | 기관·기업·언론사 이름 |
| 자료 유형 | 선택 | 뉴스, 기업 공식 홈페이지, 기술 블로그, 공식 YouTube, 보고서·공공자료, 기타 |
| 관련 산업 | 다중 선택 | 유통/커머스/리테일 |
| 관련 직무 | 다중 선택 | MD, HR |
| 업무 영역 | 다중 선택 | 아래 업무 영역 목록 사용 |
| 핵심 요약 | 텍스트 | 반드시 기억할 핵심 1~3문장 |
| 학습 상태 | 선택 | 읽기 전, 읽음, 다시 보기 |
| 수집일 | 생성 시각 | Notion 자동 기록 |

## 업무 영역

MD:

- 고객·시장 분석
- 상품·브랜드 구성
- 판매 전략
- 성과·운영 관리

HR:

- 인력 계획
- 채용·온보딩
- 평가·보상
- 교육·성장
- 조직문화·노무
- HR 데이터

## 저장 원칙

- 직접 링크와 요청형 수집은 기존 DB와 같은 템플릿을 사용합니다. 직접 링크에는 품질 등급에 따른 저장 제한을 적용하지 않습니다.
- 관련성이 낮은 산업·직무 값은 비워둡니다.
- 발행일처럼 확인되지 않은 일반 속성은 비워두며, 본문에 정보 부족을 설명하는 문장을 만들지 않습니다.
- 새 자료는 `읽기 전`으로 저장합니다.
- `학습 상태`는 사용자가 읽었는지를 나타내며 작업의 처리 상태가 아닙니다. 검수 대기·처리 상태 속성이나 별도 상태 화면은 추가하지 않습니다.
- 사용자는 학습을 마친 자료를 `읽음`, 다시 확인할 자료를 `다시 보기`로 직접 변경합니다.
- 페이지 생성 후 해당 페이지만 다시 읽어 제목, 링크, 분류와 본문을 확인합니다.
- 확인에 성공한 자료만 로컬 인덱스에 기록합니다.
- Notion 생성·확인이 불확실하면 페이지 ID·URL과 오류를 실행 기록에 남겨 해당 페이지부터 확인합니다. 새 페이지를 무조건 재생성하지 않습니다.
- `요약만` 요청에서는 DB와 로컬 기록을 변경하지 않습니다.

## 페이지 본문 표시

- 제목은 `##` 단계로 구분합니다.
- `핵심 내용`, `산업·직무 연결`, `나에게 왜 중요한가`를 기본 영역으로 유지합니다. 직접 링크에서 직무 연결·취업 준비 의미의 근거가 없으면 해당 영역은 제목까지 생략하며 핵심 내용과 출처는 남깁니다.
- `현업 사례`, `직무 관점에서 생각해볼 점`, `성과`, `별도 인사이트`, `확인 필요`는 원문 근거가 있을 때만 작성하고, 내용이 없으면 제목도 만들지 않습니다. 직접 링크에 별도 품질 검수를 요구하지 않습니다.
- 핵심 사실과 취업 준비 관점의 해석은 구분합니다.
- `확인되지 않음`, `정보 없음`, `원문에 나오지 않음` 같은 대체 문구로 빈 영역을 채우지 않습니다.
- `확인 필요`는 출처 신뢰성이나 해석에 영향을 주는 중요한 한계에만 사용합니다.
- 표시 순서는 `핵심 내용 → 현업 사례(선택) → 산업·직무 연결 → 직무 관점에서 생각해볼 점(선택) → 나에게 왜 중요한가 → 기타 선택 영역 → 출처 및 확인 정보`로 하며, 없는 선택 영역은 건너뜁니다.
- 직무 핵심 행동과 판단 기준은 글머리표당 최대 1개, 페이지 전체 최대 6개까지 굵게 표시합니다.
- `핵심 내용`, `산업·직무 연결`, `나에게 왜 중요한가`에서 각각 최대 한 곳, 페이지 전체 최대 세 곳만 노란색 배경으로 표시합니다.
- 중요도가 낮은 섹션은 하이라이트 개수를 채우기 위해 표시하지 않습니다.
- 굵게와 하이라이트는 같은 표현에 겹쳐 쓰지 않습니다.
- 출처 정보와 URL에는 강조 표시를 사용하지 않습니다.
