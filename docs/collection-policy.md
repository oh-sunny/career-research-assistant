# 자료 수집·정리 기준

## 관심 범위

- 산업: 유통/커머스/리테일
- 직무: MD, HR
- 출처: 뉴스, 기업 공식 홈페이지, 기술 블로그, 공식 YouTube, 보고서·공공자료, 기타 공개 자료

Codex가 새로 찾아오는 자료에서는 채용공고, 일반적인 직무 소개, 단순 행사 안내와 홍보 자료를 제외합니다. 직접 넣은 링크에는 이 선별 제한을 적용하지 않습니다.

## 두 가지 실행 방식

- **직접 링크 정리:** 본문 접근·중복 확인 → 기존 템플릿 요약 → Notion 저장·저장 확인. 별도 품질 검수는 하지 않습니다.
- **요청형 수집:** 요청한 직무·주제·건수로 탐색 → 품질 선별·통합 검수 → 같은 템플릿으로 요약·저장합니다. 건수가 없으면 요청 직무별 최대 2건, 직무도 없으면 HR 2건·MD 2건이 기본 목표입니다.

수집 목표는 검수와 중복 제외 후의 저장 건수입니다. 충분한 자료를 찾지 못하면 부족 건수와 이유를 알리며 억지로 채우지 않습니다. Slack과 웹 라이브러리는 각각 명시적으로 요청한 경우에만 사용합니다. 스킬을 수정한다고 예약 실행이나 링크 입력함이 생기지는 않습니다.

## 사용자 입력 URL

- 사용자가 URL을 제공하면 자동 탐색 후보보다 해당 원문을 먼저 분석합니다. 추가 탐색은 사용자가 함께 요청한 경우에만 수행합니다.
- 한 번에 최대 5개를 처리하고 대표 URL로 중복을 확인합니다. 초과한 링크는 남은 수를 알리고 다음 묶음으로 안내합니다.
- 사용자가 지정한 URL은 임의로 다른 기사로 대체하지 않습니다. 더 직접적인 원출처를 발견하면 참고 정보로 알리되, 입력 URL의 분석 결과와 구분합니다.
- 페이지가 열려도 본문 일부·로그인 화면만 보이면 읽기 성공이 아닙니다. 로그인, 유료 구독, 삭제 또는 접근 제한으로 본문을 읽지 못하면 제목이나 검색 결과 문구만으로 요약하지 않고, 이유와 본문 붙여넣기 대안을 안내합니다.
- `요약만` 또는 `저장하지 마`는 결과만 보여주고 Notion·로컬 인덱스·판단 및 실행 기록·Slack·라이브러리를 변경하지 않습니다. 이 규칙은 요청형 수집에도 동일합니다.
- 그 외에는 본문을 읽어 요약한 자료를 A/B/C 등급·출처 우선순위·최신성·자료 유형으로 탈락시키지 않고 저장합니다. `result_reviewer`를 호출하지 않으며, 사용자에게 처리 상태 관리를 요구하지 않습니다.
- 산업·직무 연결이나 취업 준비 의미의 근거가 부족하면 해당 분류·영역을 생략하되 자료는 저장합니다. 읽지 못한 내용을 추측하거나 성과를 만들어내지는 않습니다.
- 같은 URL은 기존 Notion 링크를 안내합니다. 재요약만 요청하면 원문을 다시 읽고 결과만 보여주며 기존 페이지는 덮어쓰지 않습니다. 서로 다른 직접 링크는 같은 주제라는 이유로 제외하지 않습니다.

## 출처 우선순위 — 요청형 수집만

같은 주제나 업무 영역의 후보가 여러 개면 다음 순서로 원문을 먼저 확인합니다. 출처의 이름보다 실제 본문에 담긴 업무 과정과 판단 근거의 깊이를 함께 평가합니다.

1. **현직자·실무팀의 직접 기록:** 실무 회고, 구체적인 현직자 인터뷰, 팀 블로그, 발표 원문·자막
2. **기업·기관의 상세 사례:** 문제, 실행 주체, 판단, 실행 과정, 결과와 한계를 확인할 수 있는 기업 사례, 기술 블로그, 연구·공공 보고서
3. **구체적인 전문 보도:** 역할이 확인되는 실무자 발언, 실제 기업 사례와 실행 맥락, 확인 가능한 근거를 포함한 전문 언론·산업 매체 기사
4. **일반 뉴스와 요약 자료:** 최근 산업 변화의 발견용으로 사용하고 가능한 경우 원출처를 다시 찾습니다. 본문 자체가 A등급 기준을 충족할 때만 저장합니다.

기업 공식 자료도 성과와 문화만 홍보하고 실제 업무를 보여주지 않으면 높은 순위로 취급하지 않습니다. 보도자료를 옮긴 기사, 행사 소개, 짧은 인용만 있는 기사와 재요약 글은 기본적으로 제외합니다.

- 같은 사건이면 높은 순위이면서 가장 구체적인 원문 하나만 남깁니다.
- 낮은 순위 자료를 선택할 때는 높은 순위 원출처를 찾지 못한 이유와 A등급 통과 근거를 한 줄로 기록합니다.
- 순위가 낮아도 실제 업무 과정이 더 구체적이면 내용의 깊이를 우선하며, 목표 개수를 채우기 위해 낮은 품질의 자료를 선택하지 않습니다.

## 직무 학습 자료 선별 기준 — 요청형 수집만

사용자가 확인한 [`좋은 직무 학습 자료 레퍼런스 분석`](reference-analysis.md)에서 추출한 다음 기준을 적용합니다. 레퍼런스 원문은 기준을 만들거나 수정할 때만 확인하며, 매번 수집할 때 다시 분석하지 않습니다.

직무 공부 자료는 다음 내용을 우선합니다.

- 현직자가 실제로 맡은 문제와 책임 범위
- 핵심 업무 또는 반복 업무가 진행되는 과정
- 판단의 근거, 고민과 선택의 이유
- 다른 직무·부서·고객·구성원과 협업하는 방식
- 실행 이후의 검증, 운영, 실패 또는 개선 과정
- 업무에서 사용하는 문서·도구·회의·데이터 등 구체적인 흔적

모든 항목을 충족할 필요는 없습니다. 다만 MD 또는 HR의 실제 업무·문제·판단을 구체적으로 이해할 수 있어야 합니다. 숫자는 있으면 참고하지만 필수 조건으로 요구하지 않으며, 업무 맥락과 질적인 고민이 분명하면 좋은 자료로 판단할 수 있습니다.

직무명만 언급하거나 기업문화와 성과를 홍보할 뿐 실제 업무를 거의 알 수 없는 자료는 제외합니다. 기업 한 곳의 사례를 해당 직무 전체의 표준으로 일반화하지 않습니다.

## 정리 목표

자료를 많이 요약하는 것이 아니라, 사용자가 나중에 다시 봤을 때 반드시 기억해야 할 내용만 남깁니다.

## 정리 원칙

1. 모든 항목을 억지로 채우지 않습니다.
2. 산업 또는 직무와 직접 관련된 내용만 연결합니다.
3. 유통/커머스/리테일, MD, HR과의 관련성을 과도하게 해석하지 않습니다.
4. 원문에서 확인되지 않은 성과, 의미와 배경을 추측하지 않습니다.
5. 취업 준비에 도움이 되지 않는 세부 정보와 사례 나열은 제외합니다.
6. 같은 내용을 여러 항목에서 반복하지 않습니다.
7. 원문보다 길어지지 않도록 간결하게 작성합니다.
8. 항상 “이 자료에서 사용자가 무엇을 기억해야 하는가”를 기준으로 내용을 선택합니다.
9. 원문에서 확인되지 않은 일반 정보는 `확인되지 않음`, `정보 없음`, `원문에 나오지 않음` 같은 문장으로 대신 채우지 않고 해당 속성·문장·영역을 생략합니다.

요청형 수집에서 산업·직무 관련성 또는 취업 활용 가치가 낮으면 `수집 제외`와 이유 한 문장만 남깁니다. 직접 링크는 제외하지 않고 근거 있는 내용만 저장합니다. 원문에서 확인한 사실과 취업 준비 관점의 해석은 구분합니다.

## 기본 출력

기존 템플릿의 제목과 순서를 유지합니다. 직접 링크에서 산업·직무 연결 또는 `나에게 왜 중요한가`를 근거로 설명할 수 없으면 해당 영역을 제목까지 생략합니다. 핵심 내용과 출처 및 확인 정보는 항상 남깁니다.

### 핵심 내용

원문에서 반드시 기억해야 할 사실만 2~3개로 정리합니다. 원문에서 직접 확인되는 내용만 사용하고 세부 정보와 유사 사례를 나열하지 않습니다.

### 산업·직무 연결

산업, MD, HR 중 직접적인 관련성이 높은 항목만 작성합니다. 실제 업무나 산업 변화와의 연결을 항목별 1~2문장으로 설명하고 관련성이 낮은 항목은 생략합니다.

### 나에게 왜 중요한가

취업 준비생이 이 자료를 알아둘 구체적인 이유를 2~3문장으로 작성합니다. 직무·산업 이해, 면접, 자기소개서, 기업 분석, 프로젝트·포트폴리오 중 실제로 해당하는 관점만 사용합니다. “면접에서 활용할 수 있다”는 표현에 그치지 않고 어떤 업무·문제·판단 기준을 이해할 수 있는지 설명합니다.

### 출처 및 확인 정보

확인 가능한 제목, 출처, 발행일, URL과 자료 유형만 기록합니다.

자료 유형은 다음 중 하나를 사용합니다.

- 뉴스
- 기업 공식 홈페이지
- 기술 블로그
- 공식 YouTube
- 보고서·공공자료
- 기타

`기업 공식 홈페이지`에는 기업 뉴스룸, 공식 블로그, 채용 홈페이지와 채용 블로그를 포함합니다.

### 확인 필요

자료의 신뢰성이나 해석에 영향을 주는 중요한 한계가 있을 때만 1~2문장으로 작성합니다. 일반적인 정보 부족을 표시하는 용도로 사용하지 않으며, 중요한 한계가 없으면 제목까지 만들지 않습니다.

## 선택 항목

현업 사례, 직무 관점에서 생각해볼 점, 성과와 별도 인사이트는 기본적으로 생성하지 않습니다. 원문에 직접 근거가 있고 다음 중 하나에 해당해 사용자가 반드시 알아둘 가치가 있을 때만 추가합니다.

- MD·HR의 실제 판단이나 업무 방식을 이해하는 데 중요합니다.
- 유통/커머스/리테일 산업의 변화를 이해하는 데 중요합니다.
- 면접에서 자신의 의견을 구체적으로 설명하는 데 도움이 됩니다.
- 자신의 경험과 연결해 자기소개서 소재를 발전시키는 데 도움이 됩니다.
- 기업 분석이나 프로젝트·포트폴리오 주제로 확장할 수 있습니다.

작성 기준은 다음과 같습니다.

- **현업 사례:** 문제, 담당자의 역할, 판단과 근거, 실행, 협업, 결과, 실패·수정 중 서로 연결되는 요소가 2개 이상이고 그중 판단 또는 실행이 있을 때만 만듭니다. 원문에서 확인되는 요소만 순서대로 쓰고, 없는 요소는 이름이나 대체 문구도 만들지 않습니다.
- **직무 관점에서 생각해볼 점:** 원문에 실제 선택 또는 충돌하는 목표가 있고 비교할 직무 판단 기준이 있을 때만, 근거를 한 문장으로 연결한 뒤 사용자가 판단해볼 질문 1개를 작성합니다. 정답이나 원문에 없는 내부 사정은 만들지 않습니다.
- **성과:** 원문에서 확인되는 수치나 질적인 결과가 자료의 의미를 이해하는 데 중요할 때만 작성합니다.
- **별도 인사이트:** 핵심 내용과 중복되지 않으면서 직무의 판단 기준이나 산업 변화를 이해하는 데 중요한 해석만 작성합니다.

원문에 없는 성과나 의미를 만들지 않습니다. 유의미한 내용이 없으면 제목을 포함한 해당 영역 전체를 생략합니다.

## Notion 강조 표시 규칙

Notion 본문은 제목만으로 층위를 나누는 데서 끝내지 않고, 빠르게 훑어봐도 핵심 행동과 판단 기준이 보이도록 다음 규칙을 적용합니다.

- **굵게:** 직무의 핵심 행동, 중요한 판단 기준 또는 반드시 기억할 키워드에만 사용합니다.
- 굵게 표시는 글머리표 한 개당 최대 1개, 페이지 전체 최대 6개만 사용합니다. `산업`, `MD`, `HR` 같은 구조용 항목 이름은 이 개수에서 제외합니다.
- **하이라이트:** `핵심 내용`, `산업·직무 연결`, `나에게 왜 중요한가`에서 각각 가장 중요한 문장 또는 구절 최대 1개에 사용합니다.
- 하이라이트는 페이지 전체 최대 3개이며, 중요 내용이 없는 섹션은 개수를 채우기 위해 표시하지 않습니다.
- 하이라이트 색상은 항상 `노란색 배경(yellow_bg)` 하나로 통일합니다.
- 같은 표현에 굵게와 하이라이트를 동시에 적용하지 않습니다.
- 제목, 출처, 발행일, URL, 확인 필요 내용에는 강조 표시를 사용하지 않습니다.
- 꾸미기 위한 강조는 금지하며, 강조할 가치가 분명하지 않으면 표시하지 않습니다.

## 선별·제외 판단 기록

요청형 수집의 선별 결과를 다시 확인할 수 있도록 후보마다 다음 정보만 남깁니다. 직접 링크에는 품질 등급이나 선별 탈락 기록을 만들지 않고 중복·접근 실패 등 최소 처리 결과만 남깁니다.

- 결과: `selected`, `excluded`, `duplicate` 중 하나
- 관련 직무와 업무 영역
- 적용 기준: 직무 직접성, 구체적인 업무, 질적인 학습 가치
- 원문에서 확인한 한 줄 근거 또는 제외 이유
- 원문 URL과 확인 시각

숨은 사고 과정이나 장문의 분석은 기록하지 않습니다. 저장 대상도 Notion 생성·읽기 확인에 성공한 뒤에만 영구 인덱스에 기록합니다. `excluded` 자료 기록은 본문 없이 90일만 보관합니다.

## 실행 결과 요약

기본 완료 보고는 다음만 짧게 보여줍니다.

- 직접 링크: 입력 수, 저장 수, 중복·접근 실패·저장 실패 및 미처리 링크
- 요청형 수집: 직무별 요청·저장·부족 건수와 이유
- 저장된 자료의 제목과 Notion 링크, 중복이면 기존 자료 링크
- `요약만`이면 저장하지 않았다는 안내
- Slack·라이브러리 결과는 각각 요청해 실행했을 때만 표시

요청형 수집에서 목표 개수보다 적게 선정되더라도 실패로 처리하지 않습니다. 기준을 통과한 자료가 0건인 실행도 정상 결과입니다. Notion 생성·확인 여부가 불확실하면 성공으로 표시하지 않고 반환된 페이지 ID·URL부터 확인하며 새 페이지를 반복 생성하지 않습니다.
