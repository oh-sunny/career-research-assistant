# 산업·직무 인사이트 아카이빙 시스템

직접 찾은 링크를 정리하거나 HR·MD 자료를 요청한 만큼 찾아, 기존 요약 템플릿으로 같은 Notion DB에 저장하는 개인용 Codex 스킬입니다. 직접 링크에는 품질 선별을 적용하지 않고, 새로 탐색한 자료에만 기존 품질 기준을 적용합니다.

## 바로 사용하기

현재 실습 폴더의 Codex 대화에서 다음처럼 요청합니다.

- 직접 링크: `$career-insight-archive 이 링크를 기존 템플릿으로 정리해줘: <URL>`
- 요청형 수집: `$career-insight-archive HR 뉴스 2건, MD 뉴스 2건 찾아줘`
- 저장 없이 확인: `$career-insight-archive 이 링크는 요약만 해줘: <URL>`

스킬 원본은 [`../../../.agents/skills/career-insight-archive/SKILL.md`](../../../.agents/skills/career-insight-archive/SKILL.md)에 있습니다. 스킬 이름을 매번 쓰지 않아도 해당 작업에 맞으면 선택될 수 있지만, 명확히 실행하려면 위처럼 이름을 함께 적습니다. 기존 Codex의 Notion 연결과 DB 접근 권한이 필요합니다.

완료 답변에서 **저장된 자료 제목·Notion 링크와 저장/중복/접근 실패 건수**를 확인하세요. Notion 링크를 열어 핵심 내용과 출처, 근거가 있는 직무 연결·선택 영역이 보이면 됩니다. `요약만`이면 새 페이지를 만들지 않습니다.

## 해결하려는 문제

뉴스와 기업 콘텐츠를 많이 모으는 것보다 다음 흐름을 반복할 수 있도록 만드는 것이 목표입니다.

> 직접 링크: 중복·본문 접근 확인 → 품질 선별 없이 템플릿 요약 → Notion 저장·확인
>
> 요청형 수집: 자료 발견 → 품질 선별·검수 → 같은 템플릿 요약 → 같은 Notion DB에 저장·확인

## 현재 상태

2026년 9월 19일 기준으로 두 기본 기능에 맞춰 스킬·문서·역할별 지침을 개정했습니다. **사용자가 Codex에서 시작하는 방식**이며 예약 실행, 별도 링크 입력함, 독립 웹앱을 새로 만들지는 않았습니다. Slack·웹 라이브러리 갱신은 명시적으로 요청할 때만 쓰는 선택 기능입니다.

아래는 9월 18일까지의 기존 흐름 시험 기록입니다. 이번 개정 후 실제 원문→Notion 저장 통합 시험 결과와는 구분합니다.

로컬 기록 기준 누적 현황은 다음과 같습니다.

- Notion 저장 확인 후 로컬 인덱스에 기록된 자료: 20건
- 관련 직무: HR 10건, MD 10건
- 자료 목적: 직무 공부 17건, 산업·기업 동향 3건
- 실행 기록: 수집·검토 4회, Slack 재전송 1회
- Slack 실제 전송 성공 기록: 2회
- 자동 검사: 9개 통과

Notion에서 사용자가 직접 수정하거나 삭제한 내용은 로컬 인덱스에 자동 반영되지 않으므로, 위 숫자는 현재 Notion 화면을 실시간 조회한 결과가 아니라 로컬 기록을 기준으로 합니다.

이번 개정에서 확인한 범위:

- 스킬 기본 형식과 표시 설정 검사 통과
- 역할별 에이전트 설정 5개 문법 검사와 문서 연결 검사 통과
- 기존 9개 검사 + 분류 근거 없는 직접 링크의 인덱스 호환 검사 1개, 총 10개 통과
- 실제 기사 읽기·Notion 저장·Slack 전송은 이번 개정 검증에서 실행하지 않음

## 현재 기능과 보존된 도구

- `직무 공부`와 `산업·기업 동향` 목적 구분
- 직접 입력한 URL은 본문 접근과 중복만 확인하고 별도 품질 검수 없이 기존 템플릿으로 요약·저장
- 요청형 수집에서만 채용공고와 단순 홍보·행사 자료 제외
- 현직자·실무팀 직접 기록 → 기업·기관 상세 사례 → 구체적인 전문 보도 → 일반 뉴스 순으로 원문 확인
- MD·HR의 실제 업무, 판단과 고민이 드러나는 자료 우선
- 핵심 내용, 산업·직무 연결, 취업 준비 관점 정리
- 원문에 근거가 있을 때만 현업 사례와 직무 관점의 생각할 쟁점을 추가하고, 내용이 없는 선택 영역은 제목까지 생략
- 원문 URL 정규화와 로컬 인덱스를 이용한 중복 확인
- HR 조사와 MD 조사를 나눠 동시에 진행하는 읽기 전용 에이전트
- 조사 결과의 중복·출처·발행일·원문 일치·A등급 여부 통합 검수
- Codex의 Notion 연결을 이용한 저장과 생성 페이지 재확인
- 저장에 성공한 자료만 영구 로컬 인덱스에 추가
- 저장된 자료 20건을 검색하고 MD·HR·직무별 업무 영역으로 필터링하는 로컬 HTML 뉴스 라이브러리
- 웹 라이브러리 화면 데이터 재생성 도구 보존, 기본 수집·저장에서는 실행하지 않음
- 제외·중복 판단과 실행 결과 기록 및 90일 보존 도구
- 검증된 자료만 이용한 Slack 브리핑 초안 작성
- `.env`의 비공개 설정을 이용한 `#news-briefing` 실제 전송

## 실행 흐름

```text
HR 자료 조사 ─┐
              ├─> 통합 검수 ─> Notion 저장·재확인 ─> 로컬 기록
MD 자료 조사 ─┘

직접 링크 ─> 중복·본문 접근 확인 ─> 원문 요약 ─> Notion 저장·재확인 ─> 로컬 기록
```

- 요청형 수집은 지정한 직무·주제·건수를 따릅니다. 건수가 없으면 요청 직무별 최대 2건, 직무도 없으면 HR 2건·MD 2건이 기본 목표입니다.
- 직접 링크는 한 번에 최대 5개를 처리하며 초과분은 다음 묶음으로 안내합니다. 같은 URL이면 기존 Notion 링크를 알려주고, 서로 다른 직접 링크는 같은 주제라는 이유로 제외하지 않습니다.
- `요약만` 또는 `저장하지 마`는 두 모드 모두 결과만 보여주고 Notion·로컬 기록·Slack·라이브러리를 변경하지 않습니다.
- 본문 일부·로그인 화면만 읽을 수 있으면 요약·저장하지 않고 본문 붙여넣기 대안을 안내합니다.
- 탐색 자료가 부족하면 직무별 부족 건수와 이유를 알리고 종료합니다. 직접 링크에는 A등급 탈락 기준이 없습니다.
- 예약은 별도 설정이며 이 스킬이 스스로 시작하지 않습니다. 예약이 호출하더라도 Slack·라이브러리는 명시적으로 요청된 경우에만 사용합니다.

## 핵심 원칙

- 모든 항목을 억지로 채우지 않습니다.
- 산업·직무와 직접 관련된 내용만 연결합니다.
- 원문에 없는 성과나 맥락을 추측하지 않습니다.
- 일반적인 정보 부족을 `확인되지 않음` 같은 문장으로 채우지 않습니다.
- 나중에 다시 봤을 때 기억해야 할 내용만 짧게 남깁니다.
- 성과, 별도 인사이트와 추가 질문은 취업 준비 가치가 분명할 때만 선택적으로 작성합니다.

상세 기준은 [자료 수집·정리 기준](docs/collection-policy.md), 기준을 만든 근거는 [좋은 직무 학습 자료 레퍼런스 분석](docs/reference-analysis.md), 제품 범위는 [PRD](PRD.md)를 참고하세요.

Python 3만 있으면 별도 설치 없이 실행할 수 있습니다.

```powershell

```

전체 시험은 다음 명령으로 실행합니다.

## 개인 뉴스 라이브러리 — 기존 선택 기능

`output/news-library-2026-09-18-v03/dist/index.html`에서 마지막으로 생성한 화면 데이터를 검색·필터링하고 원문·Notion 페이지로 이동할 수 있습니다. 실시간 DB 화면이 아니므로 새로 저장한 자료가 자동 반영되지는 않습니다.

이번 개정에서는 라이브러리 갱신을 기본 흐름에서 제외했습니다. 기존 파일은 보존하며, 필요할 때 Codex에 갱신을 별도로 요청할 수 있습니다. 두 기본 기능은 웹 라이브러리 없이도 완료됩니다.

현재 로컬 인덱스에는 상세 요약이 없으므로 첫 버전의 카드는 제목과 분류 중심입니다. 카드 안에서 핵심 요약까지 읽는 기능은 인덱스 확장이 필요한 다음 개선입니다.

## Slack 연결과 전송 — 필요할 때만

직접 링크 정리와 요청형 수집에는 Slack 설정이 필요 없습니다. 아래는 기존 전송 기능의 보존 문서이며, 별도 전송 요청이 없는 실행에서는 설정 파일을 읽거나 메시지를 보내지 않습니다.

프로젝트 루트의 `.env` 파일에 본인의 값을 직접 입력합니다.

```text
SLACK_BOT_TOKEN=
SLACK_CHANNEL_ID=
```

- `SLACK_BOT_TOKEN`: 프로그램이 Slack에 접근할 때 쓰는 비밀 인증값입니다.
- `SLACK_CHANNEL_ID`: 메시지를 보낼 `#news-briefing` 채널의 고유 식별값입니다.
- `scripts/settings.py`의 `get_slack_settings()`가 실행 시 이 파일을 읽습니다.
- `scripts/slack_sender.py`는 작성된 브리핑을 표준 입력으로 받아 설정된 채널에 전송합니다.
- `.env`는 Git에서 제외되며, 값이 비어 있는 `.env.example`만 공유할 수 있습니다.
- 실제 채널 전송과 오류 후 재전송 성공 기록이 있습니다.
- 전송 여부가 불확실할 때는 같은 메시지를 자동으로 반복 발송하지 않습니다.

현재 프로토타입의 Notion 저장은 API 키를 코드에서 직접 사용하는 방식이 아니라 Codex에 연결된 Notion을 사용합니다. 필요한 데이터베이스 속성은 [Notion DB 구조](docs/notion-schema.md)에 정리되어 있습니다.

## 공개 저장소 안전 기준

- 실제 `data/archive-index.jsonl`은 개인 Notion 페이지 주소가 포함되므로 Git에서 제외합니다.
- 공개할 때는 `data/archive-index.example.jsonl`만 사용합니다.
- 비밀번호, Notion 인증값 또는 API 키를 파일에 기록하지 않습니다.
- 실제 `.env`는 Git에 포함되지 않고, 빈 입력 예시인 `.env.example`만 포함할 수 있습니다.

## 현재 한계

- 매일 오전 8시 정기 실행은 이전 제안이며 실제 예약 작업은 아직 없습니다.
- 직접 링크·자료 수집은 현재 Codex에서 사용자가 요청해 시작해야 합니다. 스킬 자체는 별도 입력 화면이나 자동 실행기가 아닙니다.
- 이번 개정은 별도 유료 AI API나 서버를 도입하지 않습니다. 실행은 Codex 사용량을 소비하며 스킬이 사용량 제한을 없애주지는 않습니다.
- Notion에서 직접 수정한 내용과 로컬 인덱스는 자동 동기화되지 않습니다.
- 실제 자료의 요약과 직무 연결은 사용자가 최종 검토해야 합니다.
- 로그인·유료 구독·삭제 등으로 본문을 읽을 수 없는 URL은 제목이나 검색 결과만으로 요약하지 않습니다.
- 주간·월간 리포트, 장기 추세 분석, 채용·기업 소식 코너, 면접 질문과 자기소개서 문구 자동 생성은 현재 범위에 포함하지 않습니다.
